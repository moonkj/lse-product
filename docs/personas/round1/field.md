# 현장 실무 엔지니어 (시공·시운전·유지보수) — 1라운드 평가

> 근거: 스크린샷 r2-full / r2-main / r2-search-is7 / p2-equipment / p2-product / p2-mobile, `src/data/equipment-types.json`, `src/data/diagram.json`, `src/data/products.json`, `src/data/docs.json`, `src/content/learn.json` (커밋 51d8dd9 기준)

## 1. 나는 누구인가
- LS ELECTRIC 현장 엔지니어, 경력 8년. 수배전반 시공 감리, VCB·GIPAM·ACB 시운전(계전기 정정, 트립 시험), 인버터·MCC 유지보수를 맡음.
- 하루 업무: 현장 이동 → 명판 확인 → 매뉴얼·결선도 찾기 → 시험 → 고객 설명. 대부분 **휴대폰**으로 하고, 전기실·지하 피트는 LTE가 약하거나 안 터짐.
- 이 앱을 여는 상황: ① 명판에 적힌 모델로 매뉴얼 PDF를 바로 받을 때, ② 고객이나 신입에게 "이 반이 계통에서 무슨 역할인지" 설명할 때, ③ 구형(단종) 기기를 교체할 후속 모델을 찾을 때.

## 3. 좋은 점
- **보호 신호 흐름이 정확함**: e025 CT/PT→OCR(신호), e026 OCR→VCB "트립"(신호), e055 EMPR→MS(신호). 전력선은 실선, 신호선은 점선으로 구분되어 신입 교육에 그대로 쓸 수 있음.
- **제품 상세의 "계통 속 위치" 미니 다이어그램**(p2-product: CT/PT ⇢ OCR/OCGR ⇢ VCB)은 현장 설명용으로 아주 좋음.
- **자료 링크 품질**: VCB 상세(p2-equipment)에 VL/VH Type 매뉴얼과 UL VCB 영문 매뉴얼이 날짜와 함께 나오고, 공식 자료실 딥링크로 최신본을 받게 함. 사본을 저장하지 않고 링크만 거는 방식은 버전 관리 면에서 맞음.
- 모바일 하단 시트(p2-mobile)에서 기기명·보유 상태·학습 포인트·"자료 5→"가 한 화면에 보임.
- 공백 노드에 "실제 확인 필요"라는 단서를 단 점(gapNote). 현장 입장에서 근거 없이 단정하지 않는 것은 신뢰로 이어짐.

## 4. 문제점

### 4-1. 계통도의 기술적 오류 (diagram.json)
| 심각도 | 위치 | 내용 |
|---|---|---|
| **높음** | e009 `n-tline → n-gis154` (154kV) | 345/765kV 송전선이 **변압기 없이** 154kV GIS로 바로 들어감. 345/154kV 변전(변압기)이 빠져 있음. 신입이 "전압이 저절로 바뀐다"고 오해할 수 있음 |
| **높음** | e028·e029 `n-vcb → n-vc → n-mv-drive` (6.6kV) | 22.9kV VCB 아래에 6.6kV VC와 고압 인버터를 **강압 변압기 없이** 연결함. 22.9/6.6kV(또는 3.3kV) 변압기가 필요함 |
| **높음** | e019·e020·e021 ALTS·LBS → MOF | ALTS(예비 선로)와 LBS(상용 선로)가 **병렬로 MOF에 함께 들어감**. 두 전원을 병렬로 투입하는 구성으로 읽힘. ALTS는 상용과 예비 두 입력을 받아 출력 하나를 내는 **인입 개폐기 자체**임. 또 ALTS 입력이 `n-auto-sw`(배전 RMU) 하나뿐이라 "2회선"이 표현되지 않음 |
| **높음** | e042·e043 busway→ATS←비상발전기 | ATS **출력(부하측)이 없음**. 비상 부하(소방·승강기)로 가는 선이 없어서 ATS가 왜 있는지 설명이 안 됨 |
| **높음** | e033 `n-oil-tr → n-busway` | 유입변압기 2차가 **주차단기(ACB) 없이** 버스웨이로 바로 감. 실제 현장에서는 허용되지 않는 구성 |
| 중간 | e054·e057·e059 MS / VFD / 소프트스타터 → 같은 motor | 기동 방식 세 가지가 **전동기 한 대에 병렬**로 물려 있음. 실제로는 서로 대체하는 선택지임. 전동기를 3개로 나누거나 "택1"로 표기해야 함 |
| 중간 | 단일 VCB 노드 (e023·e027·e028·e030) | 메인 VCB 하나에서 PF·VC·몰드TR이 모두 갈라짐. 실제 수전반은 **메인 VCB + 피더 VCB × n**이고 피더마다 CT·OCR이 따로 있음. 이 구조로는 피더 반복도, 보호협조(메인 OCR ↔ 피더 OCR ↔ ACB ↔ MCCB 시간협조)도 설명할 수 없음 |
| 중간 | e035~e041 ACB가 모선 역할 | 범례에는 "모선"이 있는데 저압 모선 노드가 없음. ACB 한 대가 MCCB·SPD·콘덴서·MCC·버스웨이의 분기점이 되어 있음. 2차 메인 ACB → 저압 모선 → 피더 차단기 순서가 맞음 |
| 중간 | e012~e014 주변압기→FCL→배전선로 | 변전소 22.9kV **인출 피더 차단기**가 없음. 배전선로 보호의 시작점이 비어 있어 리클로저와의 협조를 설명할 수 없음 |
| 낮음 | e037 SPD, e004 LA | 서지보호기·피뢰기를 직렬 전력 경로처럼 그림. 실제는 병렬(대지) 접속. 접지 기호나 "병렬" 표기가 필요함 |
| 낮음 | e060 busway→servo | 서보가 분기 차단기 없이 버스웨이에 직결됨. e068 PCS→ACB 연계도 연계 차단기가 생략됨 |
| 낮음 | abbr 중복 | `step-up-tr`와 `main-tr`가 모두 **"MTR"**(r2-search-is7 L1 타일 "MTR 승압 변압기"). `ehv-gis`/`gis-154`는 둘 다 "GIS", `cast-tr`/`oil-tr`는 둘 다 "TR". 현장에서 부르는 약어로는 승압변압기는 GTR/승압TR이 자연스러움 |
| 낮음 | 전압 표기 | `meter` 전압이 "22.9kV"로 되어 있으나 실제로는 MOF 2차(110V/5A)에 연결됨. `mcb-rcbo`만 "230/400V"(IEC식)이고 나머지는 "380/220V"로 섞여 있음 |

### 4-2. 현장 사용성
| 심각도 | 내용 / 근거 |
|---|---|
| **높음** | **단종·후속 정보 전무**: `discontinued` 199/199가 false. 현장 문의의 큰 비중이 구형 기기 교체인데 "판매 중"만 보이면 오히려 잘못된 정보가 됨 |
| **높음** | **오프라인 미지원**: 서비스워커·매니페스트 없음(src·설정 검색 결과 없음). 자료는 모두 외부 자료실 링크라서 전기실에서는 열리지 않을 수 있음 |
| **높음** | **형식명 검색 불가**: 제품이 시리즈 단위(iS7, XGIPAM 등)라서 명판의 주문형식(용량·전압 코드)을 그대로 넣으면 안 걸릴 가능성이 큼. 형식 체계 해석 규칙(예: 용량-시리즈-전압 코드)도 없음 |
| 중간 | 자료 유형이 카탈로그·매뉴얼·데이터시트 3종뿐이고, 자료 수에 포함되지 않는 CAD·인증서·소프트웨어는 문구로만 안내(p2-product 하단). **결선도, 파라미터 표, 고장 코드표**를 바로 고를 수 없음. 파일 크기 표기도 없어 저속망에서 받을지 판단하기 어려움 |
| 중간 | **화면 버그**: /equipment, /product 페이지(p2-equipment, p2-product)에서 왼쪽 사이드바 스타일이 깨짐("계층 바로가기 · 보유/전체"가 큰 제목으로 줄바꿈, 범례 아이콘 겹침). 모바일(p2-mobile)에서는 L4 VCB를 보고 있는데 계층 칩은 **L5가 활성화**되어 있음 |
| 낮음 | 상세 패널에 정격(차단전류 kA, 정격전류 A) 같은 사양이 없음(CONTEXT상 미수집). 현장에서는 교체 판단의 1순위 정보 |

## 6. 다른 부서와 충돌할 것 같은 지점
- **기획/디자인 vs 나**: "기기 74종 각 1회, 한 장에 다 보이게"라는 원칙은 간결하지만 **실제 계통은 피더가 반복**되고 같은 기기가 여러 번 나옴. 나는 정확성을 위해 재등장(또는 보조 뷰)을 원함. → 메인은 개념도로 두고 상세 뷰를 따로 만드는 절충을 제안.
- **영업/마케팅 vs 나**: 영업은 보유 제품이 많아 보이고 단종품은 숨기기를 원할 것. 하지만 현장은 **단종품과 후속 모델 정보가 가장 절실함**. 또 영업은 제품 사진 타일 위주를 원하겠지만 나는 단선결선도 기호(IEC/KS) 표기를 함께 원함.
- **교육(인사·신입) vs 나**: 교육은 단순하고 예쁜 그림을 선호. 나는 단순화해도 **틀린 연결은 안 된다**는 입장(4-1 '높음' 5건).
- **보안/법무 vs 나**: 나는 정정치 예시, 고장 사례, 결선도 원본까지 원하지만 외부 공개 사이트라서 고객 현장 정보·내부 서비스 자료는 넣을 수 없음. → 공식 자료실의 공개 문서 링크와 개념 수준 설명으로 한정.
- **개발 vs 나**: 오프라인(PWA)과 PDF 캐시는 GitHub Pages 정적 배포에서 가능하지만 캐시 무효화와 용량 관리 부담이 생김. → 앱 셸과 메타데이터만 캐시하는 것으로 범위 축소.

## 7. 성공 지표
1. **계통도 기술 정합성**: 전력기술 감수자 검토에서 "틀린 연결" 0건(현재 '높음' 5건 + '중간' 4건을 해소).
2. **현장 도달 시간**: 모바일·3G 수준 스로틀 환경에서 명판의 모델 문자열 → 해당 매뉴얼 PDF 열기까지 **3탭·30초 이내** 성공률 80% 이상(현장 인력 5명 테스트).
