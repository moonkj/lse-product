# 1라운드 평가 — UX/UI 디자이너 (시니어)

> 근거: 스크린샷(scratchpad의 r2-*, p2-*, x-*), 승인 디자인 docs/design/*.dc.html, 읽기 전용으로 본 일부 코드(AppLayout, DiagramCanvas.css). p2-*는 09:35경, r2-*는 10:06경에 찍었고 레이아웃 코드는 10:01에 바뀌었다. 그래서 p2에서만 보이는 결함은 "최신 빌드에서 다시 확인 필요"로 적었다.

## 1. 나는 누구인가
- 사내 UX/UI 시니어 디자이너. 승인 디자인(Claude Design 캔버스 v1)을 맡았고, 구현이 디자인과 맞는지 검수한다.
- 하루 업무: 화면 리뷰, 컴포넌트·토큰 관리, 접근성 점검, 사용성 테스트 설계.
- 이 앱을 여는 상황: 배포 전 검수, 신입·영업 대상 사용성 테스트 준비, 다른 부서 요청을 "화면 비용"으로 환산할 때.

## 2. 이 앱으로 꼭 하고 싶은 일 Top 3
| # | 시나리오 | 현재 |
|---|---|---|
| 1 | 처음 온 사용자가 **5초 안에** "기기를 누르면 정보가 나온다"는 걸 알고 하나를 연다 | **부분**: 첫 화면 오른쪽 360px 패널이 비어 있고 "누르면 표시됩니다"라는 문장만 있다(r2-main). 승인 디자인은 VCB가 선택된 상태를 예시로 보여줬다 |
| 2 | 계통도를 한 번에 훑어보고 **공백(빨간 점선)이 어디 몰려 있는지** 파악한다 | **부분**: Gap 모드에서 강조·흐림이 분명하다(p2-gap). 다만 전체 보기(32%, r2-full)에서는 타일 글자를 읽을 수 없고 배지는 2~3px 점이라 색으로만 구분된다 |
| 3 | 기기 → 제품 → 데이터시트를 **3번 클릭 안에** 연다 | **가능**: 상세 패널의 자사 제품 → 자료 링크(p2-mobile 시트, p2-product 자료 목록). 승인 디자인의 동선과 같다 |

## 3. 좋은 점 (화면 근거)
- **커버리지를 모양+색으로 이중 부호화**: ✓◐◆✕– 배지, 미보유는 사진 대신 단선결선도 심볼과 빨간 점선(r2-main의 LA·MOF·CT/PT). 색약 사용자도 구분할 수 있고 승인 규칙과 같다.
- **Gap 모드 완성도**: 보유 기기는 흐리게, 공백은 배경+글로우로 강조하고, 상단 띠에 "홈페이지 기준이며 실제 확인 필요"라는 단서를 붙이고, 링크 복사, 같은 계층 공백 칩, 연결된 자사 제품까지 보여준다(p2-gap). 다크 모드에서도 위계가 유지된다(p2-gap-dark).
- **제품 상세가 승인 디자인과 거의 1:1**: 브레드크럼, 칩, "계통에서 하는 일", CTA 3개, 계통 속 위치 미니 다이어그램, 같은 기기의 다른 제품(p2-product, Product.dc.html 대비).
- **상태 처리 기반이 있음**: 스킵 링크, `:focus-visible` 3px 아웃라인, 페이지 로딩 문구, PageErrorBoundary, 검색 결과 없음 문구, 이미지 로드 실패 대체, 자사 제품이 없는 기기의 빈 상태(x-eq-missing).
- **검색 드롭다운이 결과 유형을 구분함**: "제품 / 기기" 라벨과 경로(L7·보유)를 보여줘서 모델명 검색 → 계통 위치로 바로 연결된다(r2-search-is7).
- 모바일 하단 시트와 "위로 올려 전체 정보 보기"는 승인 Mobile 디자인과 같다(p2-mobile).

## 5. 제안

|---|---|---|---|---|---|
| 1 | **하위 페이지 레이아웃 회귀 점검**: 사이드바 CSS가 직접 진입·새로고침 때도 적용되는지 확인하고, /product·/equipment·/gap·/learn을 데스크톱·모바일로 시각 회귀 스냅샷 | 신뢰도를 깨는 1순위 결함 제거 | S | **P0** | 없음. 이미 고쳐졌다면 스냅샷 테스트만 추가 |

## 6. 다른 부서와 충돌할 것 같은 지점
- **영업/기획**은 사양 표·가격·경쟁사 비교 등 정보를 패널에 더 넣고 싶어 하겠지만, 나는 패널을 "역할 1줄 → 제품 → 자료" 3단으로 유지하고 나머지는 상세 페이지로 보내야 한다고 본다(패널 과밀은 발견성을 떨어뜨림). 사양·가격은 외부 공개 제약 때문에 어차피 넣을 수 없다.
- **사업부/전략**은 공백(빨강)을 덜 눈에 띄게 하자고 할 수 있다(외부 공개 시 "미보유"가 부정적으로 읽힘). 나는 모양 부호화는 유지하되 문구는 "공백 후보 · 확인 필요"로 톤을 조정하는 쪽을 권한다. 강조 자체를 빼면 Gap 모드의 존재 이유가 없다.
- **교육 담당**은 투어·퀴즈를 메인 화면에 더 노출하길 원할 수 있지만, 메인의 1차 행동은 "기기 탐색"이다. 진입점은 빈 패널의 추천 카드 1개로 충분하다.
- **개발**은 의미적 줌·그룹 박스 비용을 크게 볼 것이다 → P0(회귀·온보딩)부터 하고 P1은 사용성 테스트 결과를 보고 결정하자.

## 7. 성공 지표
1. **첫 클릭까지 시간**: 처음 온 사용자 5명 테스트에서 진입 후 10초 안에 기기 1개를 여는 비율 ≥ 80%(현재 기준값은 테스트로 측정).
2. **과제 성공률**: "L4에서 자사 제품이 없는 기기 2개를 찾아라", "XGIPAM 매뉴얼을 열어라" 과제 성공률 ≥ 90%, 데스크톱·모바일 모두.
