# 2라운드 — 설계 엔지니어 (수배전반·계통 설계, 견적 지원)

> 근거: round1 8명 평가, `src/data/diagram.json`·`equipment-types.json`(51d8dd9).
> **1라운드 정정**:
> ① 좌측 메뉴 깨짐은 1라운드에서 지적하지 않았으므로 철회할 내용이 없다. VCB 정격 불일치(7.2~25.8kV vs 자료 목록 "Susol UL VCB 27/38kV")는 스타일이 아니라 자료 데이터라서 유효하다.
> ② **전동기 1대에 MS·VFD·소프트스타터가 병렬로 물린 오류**는 내가 놓쳤다. 현장(field)의 지적이 맞다.
> ③ LA·SPD를 "분기로 그렸으니 문제없음"으로 넘겼는데, 접지(대지) 표기가 없으면 직렬로 읽힐 수 있다는 field의 지적을 받아들인다(낮음).
> ④ ALTS 예비 회선을 "다른 변전소에서 온다"고 단정한 것은 과했다. **다른 피더(가능하면 다른 변전소)**로 고친다.

## I1 외부 공개 vs 공백 노출 — **조건부 찬성(분리)**
- **동의**: 임원(exec)·연구소(rnd)·마케팅(marketing)·영업(sales)의 "공백 분석(Gap 모드·공백 표·KPI·CSV)은 사내판으로" 주장. 미확인 판정이 외부에서 사실처럼 인용될 위험이 크다.
- **반박 (exec 1안·sales "숨김"안에 대해)**: 공개판 **계통도에서 LA·MOF·CT/PT 노드 자체를 빼면 안 된다.** 이 노드들을 지우면 수전설비 계통이 기술적으로 틀린 그림이 되고, 교육용으로도 쓸 수 없다. 숨기는 대상은 "공백 상태 표시"이지 노드가 아니다.
- **UX(uxui)에 대해**: 모양 부호화를 유지하자는 데는 동의한다. 다만 빨강 강조는 사내판에서만 쓰자.
- **타협안**: 공개판에서는 해당 노드를 회색 중립 타일로 두고(I3의 새 상태), 강조·집계·메모는 사내판 전용으로 한다.

## I2 계통 정확성 vs 단순화 — **찬성(전부 수정)**, 단 방식은 field와 일부 다름
field와 같은 점: 고칠 대상(345/154kV TR, 22.9→6.6kV TR, ALTS·LBS 병렬, ATS 부하, 유입TR 2차 차단기, 기동기 병렬), 메인은 개념도로 유지, **수전반 상세(메인 VCB + 피더 VCB×n, 피더별 CT-OCR)는 보조 뷰로 P1**.

| 항목 | field안 | 내 안과 근거 |
|---|---|---|
| "74종 각 1회" 원칙 | 재등장을 허용할지 결정 필요 | **참조 노드**를 허용하자. 같은 equipmentType을 가리키는 보조 노드를 흐리게 표시하고, 커버리지 집계·검색에서는 빼서 "74종" 통계를 보존한다. 345/154kV TR은 `main-tr` 참조, 22.9/6.6kV TR은 `cast-tr` 참조, 유입TR 2차 차단기는 `acb` 참조로 처리 |
| 기동기 병렬 | 전동기 3개로 분리 또는 "택1" | **"택1 그룹" 표기를 일반 규칙으로.** 노드를 늘리지 않으면서 대체 관계를 정확히 표현한다. 같은 규칙으로 아래 두 건도 해결된다 |
| ALTS·LBS 병렬 | ALTS를 2입력 1출력 인입 개폐기로 재배치 | 재배치에 동의한다. 여기에 더해 **"1회선 수전(ASS) / 2회선 수전(ALTS)" 택1 그룹**으로 묶는다. 둘이 동시에 MOF에 들어가는 그림을 남기면 다시 병렬 투입으로 읽힌다 |
| **VCB 뒤 PF 직렬** | field 목록에 없음 | **이건 높음이다.** PF는 차단기를 대신하는 방식(LBS+PF, PF형 수전)이다. 학습 포인트 "차단기 대신 경제적으로"와 그림이 서로 모순된다. PF를 VCB 아래에서 떼어 **22.9kV 모선의 "CB형 / PF형" 택1**로 둔다 |
| 저압 모선 | ACB가 모선 역할을 하므로 모선 노드 필요 | 동의한다. "모선"은 기기가 아니라 굵은 선(범례에 이미 있음)으로 그리고, 노드 수에는 넣지 않는다 |
| ATS 부하 | 비상부하 추가 | 동의한다. `na` 상태의 부하 노드 1개를 추가한다(75종이 됨). 아니면 `lighting-outlet` 참조 노드로 처리 |
| 변전소 22.9kV 인출 차단기 | 중간 | L2·L3은 내 설계 범위 밖이라 P2로 미뤄도 된다고 본다 |

- **양보선**: 보조 뷰와 심볼 토글은 P1~P2로 미룰 수 있다. 하지만 **틀린 연결을 그대로 공개하는 것은 양보할 수 없다.** 교육팀이 원하는 단순함은 택1·참조 노드로 지킨다.
- 이 수정은 기존 화면 요소를 바꾸는 일이므로 사용자 승인을 받은 뒤 진행한다.

## I3 공백의 정의 — **찬성(새 상태 + 근거 필드)**
- **동의**: 연구소(rnd)의 `evidence / verifiedBy / verifiedAt / confidence` 필드, 임원(exec)의 공백 검증 스프린트.
- **추가 제안**: **"패널 구성품"**은 계통상 역할을 기준으로 한 속성으로 둔다(LA·MOF·CT/PT. 실제 조달 방식은 구매·설계팀 확인 전에는 쓰지 않는다). 소유 여부는 이와 별개 축으로 관리한다.
  - 영업(sales)의 "협력 조달" 문구는 사실 확인이 끝난 뒤에만 쓴다.
  - 연구소(rnd)의 **정격 범위 기반 일부 보유 판정**에도 동의한다. 예: VCB는 데이터상 25.8kV인데 자료 목록에는 38kV가 있음. GIS·승압TR은 최고 전압 등급 확인이 필요하다.

## I4 영업 발표 모드 — **조건부 찬성**
- 공백 표시를 중립화하고 범위를 축약하는 것은 괜찮다. 단, **연결을 바꾸거나 구성품을 숨기는 것은 금지**한다.
- 영업(sales)의 업종 프리셋(빌딩·공장·데이터센터·신재생)은 내 표준 계통 템플릿과 같은 데이터 구조다(노드 부분집합 + 택1 선택). 그러니 **하나로 만들자.**

## I5 교육 품질 — **찬성(신입·HRD안 지지)**
- 신입·HRD(newbie)의 검토 메타(`reviewedBy/At/sourceDoc`)와 투어 속 공백 표시 접기를 지지한다.
- 설계 관점에서 덧붙일 것:
  - I2 수정 후 **학습 포인트·퀴즈를 계통도와 대조 검수**해야 한다(PF, ALTS, 기동 방식).
  - 퀴즈 기술 검수에 설계/기술팀이 참여한다.
- 완료 기준은 HRD안을 따른다.

## I6 다음 분기 우선순위
- **정격 데이터**: P1로 둔다. 공개 카탈로그 범위만 쓰고 노력 L이다. 그러나 영업·현장·연구소 세 부서가 공통으로 요구한다.
- **단종·후속 모델**: field 주장대로 P1이다.
- **온보딩, 의미적 줌, PWA, OG**: 정확성이 확보된 뒤에 한다.

## 내가 꼽는 P0 3개
1. **계통 연결 오류 7건 수정 + 표현 규칙(택1 그룹·참조 노드·모선 선) + 설계/기술 검수 서명**. 틀린 그림은 교육·영업·공개 모두에 해를 준다.
2. **공개판·사내판 분리**: 공백 강조·집계·CSV는 사내판에서만 쓴다. 공개판은 노드를 유지하되 중립 표시한다. 여기에 공백 판정 근거 필드와 "패널 구성품" 속성을 함께 넣는다(I1+I3).
3. **콘텐츠 검수 메타 체계**: 기기 설명·전압·학습 포인트·퀴즈에 검토 부서·검토일·근거를 기록하고, 검토 전 항목에는 "초안" 배지를 단다.
