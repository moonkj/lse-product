# 2라운드 교차 토론: 연구소(R&D) 책임연구원

> 근거: round1/ 8개 평가, 최신 스크린샷 cur/gaptable.png(51d8dd9), equipment-types.json, products.json
> **스스로 정정할 것**: 1라운드에서 나는 사이드바 깨짐을 근거로 쓰지 않았으므로 철회할 주장은 없다. 다만 1라운드 제안 4("DC·디지털 변전소·HVDC 하위 노드를 메인 계통도에 추가")는 I2·I1과 충돌한다. 노드를 늘리면 공개되는 공백 수도 함께 늘기 때문이다. 그래서 **메인이 아니라 보조 뷰/트렌드 오버레이**에 두는 것으로 고친다. "화면에 데이터 기준일이 없다"는 지적은 cur/gaptable.png에서도 기준일이 보이지 않아 그대로 유지한다.

## I1 외부 공개 vs 공백 노출: **찬성(분리)**
- **동의**: 임원(제안 1), 영업(제안 3), 마케팅(제안 1). **부분 반박**: UX는 "강조를 빼면 Gap 모드의 존재 이유가 없다"고 했는데, 나는 강조를 빼자는 것이 아니다. 강조는 **사내판에서 그대로 유지**하자는 것이다.
- 근거: 공백 12건 중 11건이 미확인 문구다. 확인되지 않은 약점 목록을 공개하면 틀릴 경우 자사 손해가 되고, 맞더라도 경쟁 정보가 된다. 게다가 R&D가 공백 화면에 넣고 싶은 것(기술 인접도, 로드맵 후보)은 **공개판에는 절대 넣을 수 없다**. 공개판에 묶여 있는 한 공백 기능은 연구 도구로 성장할 수 없다.
- 타협선: 사내 호스팅이 결정되기 전에는 공개 빌드에서 Gap 모드·/gap·CSV·KPI를 끄고, 제품 모드의 미보유 타일은 회색 중립("본 맵 미등록")으로 둔다. 계통 위치는 남긴다. 설계 평가대로 LA·MOF가 계통에서 빠지면 교육이 틀어지기 때문이다.

## I2 계통 정확성 vs 단순화: **찬성(정정 우선), 74종 원칙은 조건부 완화**
- **동의**: 현장(4-1)과 설계(4장)의 오류 지적. 특히 345/154kV TR, 22.9/6.6kV TR 누락은 전압이 기기 없이 바뀌는 오류라 교육용으로는 치명적이다. **반박**: "74종 각 1회"를 지키려고 틀린 연결을 남기는 것에는 반대한다.
- 근거: 오류를 고치면 강압 TR, 피더 VCB, 저압 모선 같은 노드가 늘어난다. 원칙을 "**기기 종류 74종 + 같은 종류의 재등장(인스턴스) 허용**"으로 바꾸면 커버리지 집계는 종류 기준을 유지하므로 보유율 계산에 영향이 없다.
- 타협선: 메인은 개념도로 두고 오류 6건만 고친다(노드 +3~5). 피더 반복·보호협조는 설계가 제안한 "수전반 상세/표준 템플릿" 보조 뷰로 보낸다. R&D 트렌드(DC 배전·디지털 변전소·HVDC) 상세도 같은 보조 뷰 틀을 함께 쓴다.

## I3 공백의 정의: **찬성(상태 세분화 + 근거 필드 필수)**
- **동의**: 설계("LA·MOF·CT/PT·DS·COS는 원래 패널에 타사품을 넣는다, 공백 = 사업 기회로 단정 금지"), 영업("협력 조달 맥락 없음"). 임원 제안 2(검증 스프린트)와 HRD 제안 1(검토 메타)은 같은 스키마로 통합하자.
- 내 입장: R&D에게 "공백"은 **우리가 만들 수 있는데 안 만드는 것**과 **만들 이유가 없는 것**을 구분해야 의미가 있다. 커버리지(보유 여부)와 공급 방식(자체/계열사/패널 내 조달/미취급)은 **서로 다른 축**이므로 한 필드에 섞지 말아야 한다.
- **스키마 제안** (equipment-types.json 각 기기에 추가):
```jsonc
"coverage": "owned|partial|affiliate|sourced|missing|na",   // sourced 신설 = 패널 구성품·타사 조달
"gapAssessment": {
  "supplyMode": "in-house|affiliate|panel-sourced|not-offered|unknown",
  "basis": "homepage-menu|catalog|bu-confirmed|rnd-confirmed",   // 판정 근거 종류
  "confidence": "candidate|confirmed",           // candidate면 화면에 "공백 후보" 고정
  "evidence": [{ "type": "url|doc|meeting", "ref": "https://… 또는 문서번호", "note": "공개 가능 문구" }],
  "verifiedBy": "부서명(실명 금지)",              // 예: "전력기기사업부 제품기획팀"
  "verifiedAt": "2026-12-05",
  "reviewDue": "2027-06-05",                     // 6개월 재확인, 지나면 자동으로 candidate 강등
  "ratingScope": { "required": "7.2~38kV", "offered": "7.2~25.8kV" },  // 정격 기준 partial 판정(선택)
  "publicNote": "공개판 노출 문구",
  "internalRef": "사내판 오버레이 키"             // 로드맵·인접도·전략옵션은 공개 JSON에 넣지 않음
}
```
  - 공개 JSON에는 `internalRef`까지만 둔다. 기술 인접도·로드맵·임원이 제안한 전략 옵션은 **사내 오버레이 JSON**(비공개 저장소)에 둔다.
  - `basis = homepage-menu`이면 `confidence`는 반드시 `candidate`로 둔다(검증 규칙). `pcs`처럼 owned인데 확인 메모가 붙은 모순은 이 규칙으로 걸러진다.
  - `ratingScope`는 설계가 지적한 VCB 사례(voltage 7.2~25.8kV, 자료에는 UL VCB 27/38kV)처럼 정격 기준 판정의 근거가 된다.
- 타협선: `sourced` 신설이 화면을 바꾸는 것이 부담이면, 우선 데이터 필드(`supplyMode`)만 채우고 표시는 기존 5상태를 유지한다. 단, 공백 표 집계에서 panel-sourced는 "미보유" 수에서 뺀다.

## I4 영업 발표 모드: **조건부 찬성**
- 영업 제안 2에 동의한다. 다만 "협력 조달"이라는 표기는 I3의 `supplyMode = panel-sourced`로 **확인된 기기에만** 허용하고, 미확인 기기는 "본 맵 미등록"으로 둔다. 확인되지 않은 것을 긍정 표현으로 덮는 것도 부정확하기는 마찬가지다.
- 타협선: 발표 모드는 공백을 숨기는 필터일 뿐 데이터를 바꾸지 않는다. 화면 하단에 "일부 기기는 표시하지 않음"을 한 줄로 고지한다.

## I5 교육 품질: **찬성(HRD안 지지)**
- HRD 문제점 3(투어에 미확인 공백 노출)에 동의한다. 투어의 "이 계층의 공백"은 `confidence = confirmed`인 항목만 보여 주고, 후보는 접어 둔다. 퀴즈 검토 메타(`reviewedBy/At/sourceDoc`)는 I3 스키마와 필드명을 통일하자.

## I6 다음 분기 우선순위
- 정격 데이터는 **P1**이다. I3의 `ratingScope`로 공백 기기와 partial 판정 기기부터 범위를 좁혀 시작한다. 단종·후속 모델(현장 제안 3)은 P1에 동의한다. R&D에게도 세대·플랫폼 관계가 필요하다. 의미적 줌·PWA·OG·분석은 P2로 본다.

## 내가 꼽는 P0 3개 (전체 관점)
1. **공개판/사내판 분리**: 공개 빌드에서 Gap·/gap·CSV·KPI를 끄고, 사내 오버레이 구조를 마련한다. 임원·영업·마케팅·R&D 공통 요구다.
2. **계통도 오류 6건 정정 + 설계팀 검수 서명**: "종류 74 + 인스턴스 재등장 허용"으로 원칙을 바꾼다. 현장·설계·HRD 공통 요구다.
3. **공백 판정 스키마(위 I3) 도입 + 15건 검증 스프린트**: 4주 안에 `confidence = confirmed` 비율 100%. 임원 제안 2, HRD 제안 1과 통합한다.
