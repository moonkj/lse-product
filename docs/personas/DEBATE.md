## 2. 1라운드 요약

### 전력사업 임원
- Top3: ① 공백을 매출 기회순 정렬해 만들기/사기/제휴/버리기 결정 — **불가**(메모 12건 중 11건 동일 문구, 전략 필드 없음) ② 매트릭스를 경영회의 자료에 첨부 — **부분**(CSV만, 기준일 없음) ③ 공백과 연결된 자사 제품으로 번들 효과 판단 — **부분**
- 핵심 문제: 외부 공개 사이트에 미검증 "미보유 12건" 노출(높음) / 공백 데이터가 초안이라 76%가 경영회의에 인용되면 오판 위험(높음) / 보유율 분모가 기기 종류 수(중간)
- 공백 표 사이드바 글자 겹침(낮음) → **2라운드에서 철회**
- 핵심 제안: 공개판에서 Gap 제거·사내판 분리(P0), 공백 검증 스프린트(P0), 공식 고지(P0), 사내판 전략 필드(P1), 경영 보고 1장 내보내기(P1), 가중 커버리지(P2)

### UX/UI 디자이너
- Top3: ① 5초 안에 "기기를 누르면 정보가 나온다" 파악 — **부분**(첫 화면 오른쪽 패널이 빈 안내문) ② 전체 보기에서 공백 군집 파악 — **부분**(32%에서 글자·배지 모양이 안 보임) ③ 기기→제품→데이터시트 3클릭 — **가능**
- 핵심 문제: 하위 페이지 사이드바 스타일 깨짐(높음) → **2라운드에서 철회** / 첫 화면 발견성(높음) / 74종 전체 보기의 인지 부하(높음) / 상태 불일치(모바일 칩 L5, 검색 시 사이드바 L1·L2 강조, 1/7인데 "투어 완료")(중간)
- 핵심 제안: 회귀 점검(P0, 철회), 첫 화면 온보딩(P0 → 2라운드 P1), 의미적 줌(P1), 상태 동기화 버그 묶음(P1), 승인 디자인과의 차이 결정(P1)
- 공백 표현: 강조 유지, 문구만 "공백 후보 · 확인 필요" (→ 2라운드에서 분리안으로 선회)

### 현장 실무 엔지니어
- Top3: ① 명판 형식명 → 매뉴얼·결선도 3탭 — **부분**(시리즈 단위만 검색) ② 단종품 → 후속 모델 — **불가**(`discontinued` 199건 모두 false) ③ 수전반 구성·보호협조 설명 — **부분**(틀린 연결 다수)
- 핵심 문제: 계통도 기술 오류 '높음' 5건(345/154kV TR 없음, 22.9/6.6kV TR 없음, ALTS·LBS 병렬, ATS 부하 없음, 유입TR 2차 ACB 없음) / 단종 정보 전무·오프라인 미지원·형식명 검색 불가(높음)
- /equipment·/product 사이드바 깨짐 → **2라운드에서 철회** (모바일 칩 L5 활성은 유지)
- VCB→PF→유입TR을 오류로 보지 않음 → **2라운드에서 설계 지적을 받아 오류로 정정**
- 핵심 제안: 계통 오류 정정(P0), 단종·후속 연결(P0~P1), 화면 버그(P0), 수전반 상세 보조 뷰(P1), 모바일 현장 모드·PWA(P1), 형식명 검색(P1)

### 연구소 책임연구원
- Top3: ① 공백별 이유·기술 인접도·시장성으로 신제품 후보 순위 — **불가** ② 기술 트렌드(DC·ESS·디지털 변전소·HVDC)별 라인업 — **부분**(1노드씩 뭉뚱그림) ③ 제품 세대·정격 비교 — **불가**
- 핵심 문제: 공백 판정 기준이 "홈페이지에 있나" 하나뿐(높음) / 보유 판정이 카테고리 수준이라 과대평가 가능(`ehv-gis`, `step-up-tr` 전압 확인 메모가 JSON에서 사라짐)(높음) / 외부 공개 노출(높음)
- 핵심 제안: 근거 필드(`evidence/verifiedBy/verifiedAt/confidence`)(P0), 공개/사내 분리(P0), 정격 범위 기반 partial 판정(P1), 트렌드 하위 노드(P1 → 2라운드에서 메인이 아니라 보조 뷰로 수정), 세대·기준일·갱신 체계(P2)

### 설계 엔지니어
- Top3: ① 정격("24kV 25kA 630A VCB")으로 기기 찾기 — **불가** ② CT→계전기→VCB, ACB-MCCB 협조 보기 — **부분** ③ 프로젝트 유형별 표준 계통 — **불가**
- 핵심 문제: 345/154kV TR 누락, 22.9→6.6kV TR 누락, **VCB 뒤 PF 직렬**, 유입TR 2차 주차단기 없음(모두 높음) / ALTS·LBS 병렬, ATS 출력 없음, 단일 VCB·모선 없음, 수전 필수 기기(DS·COS·NGR) 누락(중간) / VCB 정격 7.2~25.8kV vs 자료 "UL VCB 27/38kV"(중간)
- 기동기 병렬은 지적하지 않음 → **2라운드에서 현장 지적을 수용**
- 핵심 제안: 계통 오류 수정(P0), 설계팀 서명 검수(P0), 대표 정격 범위(P1), 표준 계통 템플릿(P1), 심볼 토글(P2), 보호협조 카드(P2)
- 충돌 예고: "LA·MOF·CT/PT·DS·COS는 패널에 타사품을 넣는 기기라 공백=사업 기회로 단정 불가"

### 기술영업
- Top3: ① L4~L7+EMS만 띄워 라인업 설명 — **부분** ② 카탈로그 링크/QR 즉시 전달 — **부분**(링크 복사는 Gap 모드에만) ③ 수전반 패키지 묶어 보여주기 — **불가**
- 핵심 문제: 제품 모드에서도 공백이 빨간 점선 "자사 제품 없음"으로 노출(높음) / 외부에 공백 표·CSV·76% 공개(높음) / 사이드바 깨짐(높음) → **2라운드에서 철회**
- 핵심 제안: 사이드바 수정(P0, 철회), 발표 모드(P0 → 2라운드 P2로 양보), 공백 외부 비노출(P0), 공유 버튼·QR(P1), 업종 시나리오 필터(P1), 패키지 카드(P1)

## 3. 2라운드 쟁점별 토론

### I1. 외부 공개 vs 공백 노출
공개 사이트(GitHub Pages)에 미확인 공백 12건·보유율 76%·CSV가 그대로 보인다. 공개판/사내판을 나눌지, 공개판에서 공백을 어떻게 표현할지.

| 페르소나 | 입장 | 요지 |
|---|---|---|
| 임원 | 찬(분리) | 문구를 바꿔도 미검증 목록이 나가는 건 같다. 공개판은 ① Gap·/gap·KPI 끄기(최소안) 또는 ② 회색 "본 맵 미등록" |
| UX | 조건부 찬(분리) | **1라운드 입장 철회.** 시각 강조 크기는 데이터 확신도에 비례해야. 공백 노드 삭제는 반대, 회색 심볼 + "본 맵 미등록" |
| 현장 | 조건부 찬 | 타일 자체는 남겨야 수전 계통이 안 끊김. 공개판은 회색 심볼 + "구성품(별도 조달)" |
| 연구소 | 찬(분리) | 로드맵·인접도는 공개판에 못 넣으니 공백 기능이 성장하려면 분리 필요. 계통 위치는 남김 |
| 설계 | 조건부 찬 | 숨길 대상은 "공백 상태 표시"이지 노드가 아님. 빨강은 사내판만 |
| 영업 | 찬(분리) | 고객은 단서 문구보다 빨간 ✕를 먼저 읽음. CSV 다운로드는 문구로 못 막음. "본 맵 미등록" 채택 |
| 마케팅 | 찬(분리) | 공개판은 Gap·/gap·CSV·숫자 끄고 "본 맵 미등록 · 공식 문의". 사내판은 UX 안 그대로 |
| 신입·HRD | 조건부 찬 | 교육은 로그인 없이 공개 유지. 공개판 투어에서 공백 박스 제거, 사내판 투어는 "확인 필요"·접힘 |

**주요 공방**
- 임원이 "UX의 '강조 유지·문구만 조정'은 미검증 12건이 외부에 나간다는 사실을 바꾸지 못한다"고 반박하자, UX는 2라운드에서 **스스로 1라운드 안을 거두고 분리안으로 선회**했다(근거: "11건이 같은 미확인 메모인데 빨간 위계를 주면 확정 사실처럼 읽히는 디자인 오류").
- 영업·마케팅·연구소도 UX 1라운드 안을 반박했다. 연구소는 "강조를 빼자는 게 아니라 사내판에서 유지하자는 것"이라고 UX의 "강조를 빼면 Gap 모드의 존재 이유가 없다"에 부분 반박했다. 임원·영업·마케팅도 "UX 강조 디자인은 사내판에서 유지"로 양보했다.
- 설계가 "임원 1안·영업 '숨김'안처럼 공개판에서 LA·MOF·CT/PT 노드를 빼면 계통이 틀린 그림이 된다"고 반박했다. UX·현장·연구소도 같은 이유로 노드 삭제에 반대했다. 그 결과 2라운드에서는 8명 모두 "노드는 남기고 상태 표시만 중립화"로 모였다.
- 신입·HRD는 UX 안을 "사내판 Gap 모드에서는 찬성"하면서도, cur/learn.png L4 단계의 빨간 박스("이 계층의 공백 — 자사 제품 없음: LA·MOF·CT/PT")를 근거로 **교육 투어는 따로 다뤄야 한다**고 주장했다.
- 문구 이견: "본 맵 미등록"(UX·영업·연구소·임원 ②안), "본 맵 미등록 · 공식 문의"(마케팅), "구성품(별도 조달)"(현장).

**합의점**: 공개판/사내판 분리(8/8). 공개판에서 Gap 모드·/gap·CSV·커버리지 KPI 제외. 공백 노드는 계통에 남기고 회색 중립으로 표시. 빨간 강조는 사내판에서 유지.
**남은 이견**: 공개판 라벨 문구, 사내 호스팅 방식(미정), 공개판 투어에서 공백 박스를 아예 뺄지(신입·마케팅) 아니면 confirmed만 보일지(연구소).

### I2. 계통 정확성 vs 단순화
설계·현장이 지적한 연결 오류를 고치면 노드가 늘어난다. "74종 각 1회" 원칙을 지킬지, 보조 뷰를 둘지.

| 페르소나 | 입장 | 요지 |
|---|---|---|
| 임원 | 찬(정정 우선) | 틀린 계통은 공백 노출과 같은 급의 브랜드 리스크. 반복 노드 허용, "종류 74"와 "노드 수"를 따로 표기. 보조 뷰 P1 |
| UX | 찬, 원칙 완화 | 74→약 78개라 시각 부하 미미. 승인 디자인의 그룹 박스 규칙으로 재등장을 표현, 재등장 노드에 "2" 표기 |
| 현장 | 찬, 원칙 **조건부 유지** | 장비 타일은 74종 그대로. 비장비 요소 3종(모선·참조 타일·끝점 라벨)과 `kind: alt`(택1)를 추가하고 집계에서 제외 |
| 연구소 | 찬, 원칙 조건부 완화 | "종류 74 + 인스턴스 재등장 허용"이면 보유율 계산에 영향 없음. 트렌드 하위 노드는 보조 뷰로(자기 수정) |
| 설계 | 찬(전부 수정) | 참조 노드(흐리게, 집계·검색 제외) + "택1 그룹" 일반 규칙 + 모선은 굵은 선. 틀린 연결 공개는 양보 불가 |
| 영업 | 찬, 조건부 | 원칙에 집착 안 함. 단 메인에 노드를 계속 더하는 건 반대. 업종 시나리오 = 설계 템플릿 = 현장 수전반 상세 |
| 마케팅 | 찬(정정 우선) | "74종 각 1회"는 브랜드 약속이 아님. 템플릿 명칭은 마케팅 검수 |
| 신입·HRD | 찬, 복잡도 상한 | 오류는 모두 수정하되, 피더 반복·DS·COS·NGR·IEC 심볼·DC/HVDC 하위 노드는 메인에 넣지 않음. 수치 상한 제시 |

**주요 공방**
- 설계가 1라운드에서 "VCB 뒤 PF 직렬은 실무에 없다(PF는 차단기 대신 LBS와 조합)"고 지적했다. 현장은 2라운드에서 "1라운드에 피더 보호로 볼 수 있다며 넘어갔는데 잘못 봤다"며 **설계 지적을 받아 오류 목록에 추가**했다. 다만 설계 2라운드 문서는 현장 1라운드 목록을 기준으로 "field 목록에 없음, 이건 높음"이라고 적었다(같은 시점에 쓴 문서라 서로의 수정을 반영하지 못함).
- 반대로 현장이 지적한 "전동기 1대에 MS·VFD·소프트스타터 병렬"은 설계가 1라운드에서 놓쳤다. 설계는 2라운드에서 **"field 지적이 맞다"며 수용**하고, 이를 "택1 그룹" 일반 규칙으로 키웠다. LA·SPD 접지 표기(현장 지적)도 수용했고, ALTS 예비 회선을 "다른 변전소"라고 한 단정은 "다른 피더(가능하면 다른 변전소)"로 고쳤다.
- 신입·HRD와 UX가 연구소 1라운드 제안(DC·HVDC·디지털 변전소 하위 노드를 메인에 추가)을 반박했다. 연구소도 2라운드에서 "노드를 늘리면 공개되는 공백 수도 는다"며 **보조 뷰/트렌드 오버레이로 스스로 수정**했다.
- 신입·HRD는 현장·연구소가 원하는 범위(피더 × n, 보호협조, DS·COS·NGR, IEC 심볼)를 메인에 넣는 데 반대했다. 대신 "반드시 정확 5기준 / 생략 허용 / 보조 뷰 / 수치 상한"을 제시했다(§4 참조). 현장도 피더 VCB는 반복해 그리지 않고 "×n" 주석으로 처리하는 안을 냈다.
- 74종 원칙 처리: 현장은 "장비 74종 유지 + 비장비 요소" (원칙 조건부 유지), 설계·신입은 "참조 노드/타일(집계 제외)", 임원·연구소·마케팅은 "재등장 허용", 영업은 "메인 노드 추가 최소화"로 갈렸다.
- 보조 뷰: 영업은 "업종 시나리오 = 설계 표준 템플릿 = 현장 수전반 상세"라고 했고, 설계는 I4에서 "업종 프리셋과 템플릿은 같은 데이터 구조(노드 부분집합 + 택1)이니 하나로 만들자"고 했다.

**합의점**: 오류 정정은 P0(8/8). 반영 전 설계팀 1인 검수·서명, 검수일 표기. 수전반 상세·표준 템플릿·업종 시나리오는 P1 보조 뷰. 재등장 요소는 커버리지 집계에서 제외. 화면을 바꾸므로 사용자 승인 후 반영(현장·설계·영업 명시).
**남은 이견**: 재등장 표현 방식(참조 타일 / 그룹 박스 반복 / 새 기기 종류), PF·ATS 수정 방식(§4), 변전소 인출 차단기 우선순위(현장 P1, 설계 P2).

### I3. 공백의 정의
LA·MOF·CT/PT처럼 패널에 타사품을 넣는 구성품도 '미보유'인가? 새 상태와 판정 근거 필드.

| 페르소나 | 입장 | 요지 |
|---|---|---|
| 임원 | 찬(새 상태 + 근거 필드) | **자기 수정**: 12건 전체를 M&A·제휴 후보처럼 봤던 것을 고쳐 패널 구성품을 분리. 범례 5개 유지, "타사 조달"은 미보유의 하위 배지로도 가능. 근거 필드는 필수 |
| UX | 찬 | "패널 구성품·타사 조달"을 6번째 상태로. 모양 부호화 유지, 확신도는 선 스타일(후보 점선 / 확정 실선), 범례 6개 이하 |
| 현장 | 찬 | "패널 구성품(조달)". 고객에게는 "LS 납품". 단 사업부 확인 필요, 본인은 단정할 근거 없음 |
| 연구소 | 찬(세분화 + 근거 필수) | 커버리지와 공급 방식은 다른 축. 스키마 제안(§5). `basis=homepage-menu`이면 `candidate` 강제 |
| 설계 | 찬 | "패널 구성품"은 계통상 역할 속성이고 소유와는 별개 축. 조달 방식은 구매·설계 확인 전엔 미기재. 정격 기반 partial 판정 동의 |
| 영업 | 찬(새 상태) | 수배전반 견적에서 이 기기들은 반 안에 포함됨. "패널 구성품(수배전반에 포함해 공급)". 검증 스프린트에 영업 참여 |
| 마케팅 | 찬 | "수배전반에 포함해 공급"은 외부에도 긍정 메시지. 확인 전엔 사용 안 함. 공개판은 confirmed만 상태 표기 |
| 신입·HRD | 찬 | 신입이 배울 것은 "우리는 MOF가 없다"가 아니라 사업 구조. 상태명·판정은 사업부가 정하고, 판정 전엔 교육 화면에 미표시 |

**주요 공방**
- 설계가 1라운드에서 "LA·MOF·CT/PT·DS·COS는 원래 패널에 타사품을 넣으므로 공백=사업 기회로 단정 불가"라고 지적했다. 임원은 이를 받아 **1라운드의 '공백 전체 = 전략 후보' 시각을 수정**했다. 패널 구성품(LA·MOF·CT/PT)을 "패널 구성품·타사 조달"로 나누고, 남는 발전기·비상발전기·리클로저·APFC·ATS 등을 진짜 전략 공백으로 봤다.
- 임원은 "상태가 6개로 늘면 범례가 복잡해진다는 UX 우려"를 받아들여 메인 범례는 5개로 두자고 했다. UX 자신은 2라운드에서 6번째 상태에 찬성하고 "범례 6개 이하, 넘으면 접기"를 조건으로 걸었다.
- 영업이 1라운드에서 낸 "협력 조달" 문구에 대해 설계·마케팅·연구소·신입이 모두 "사실 확인 뒤에만" 쓰자는 조건을 달았다. 영업도 2라운드에서 "확인 전에는 '공백 후보' 유지(지어내지 않음)"로 맞췄다.
- 연구소와 설계는 "커버리지(보유 여부)와 공급 방식은 서로 다른 축"이라는 데 뜻을 같이했다. 다만 연구소 스키마는 `coverage`에 `sourced` 값도 새로 넣는다.
- 연구소는 임원 제안 2(검증 스프린트)와 HRD 제안 1(검토 메타)을 같은 스키마로 통합하자고 제안했다. I5에서는 필드명 통일도 요구했다.

**합의점**: 근거 필드(출처·확인 부서·확인일·확신도) 도입(8/8). 패널 구성품을 별도로 구분(8/8, 이름·표시 방식은 미정). 확인 전에는 "공백 후보" 유지. 검증은 사업부가 수행.
**남은 이견**: 화면에 6번째 상태로 띄울지(UX·현장·영업·마케팅), 범례 5개 + 하위 표기(임원), 데이터만 채우고 표시는 기존 5상태(연구소 타협안), 속성으로 별도 축 관리(설계). 상태 이름도 갈림(§8).

### I4. 영업 발표 모드
`?mode=present`(공백 중립·범위 축약·UI 최소화)가 정직성·교육 목적과 충돌하는가.

| 페르소나 | 입장 | 요지 |
|---|---|---|
| 임원 | 조건부 찬 | 공개판에서 공백을 끄면 공개판이 곧 발표 모드 → I1 분리로 흡수. "협력 조달"은 검증된 항목만(과장 광고 리스크) |
| UX | 조건부 찬 | 별도 모드는 화면 상태 3중(제품/Gap/발표)이라 비용 큼. 공개판에 "발표 보기" 토글(크롬 숨김·글자 확대)만 |
| 현장 | 조건부 찬 | 연결은 줄이지 않음(타일 숨김 금지, 회색만), 화면에 "발표 모드" 표시 |
| 연구소 | 조건부 찬 | "협력 조달"은 `panel-sourced` 확인 기기만. 발표 모드는 데이터를 안 바꾸는 필터, 하단에 "일부 기기는 표시하지 않음" |
| 설계 | 조건부 찬 | 연결 변경·구성품 숨김 금지. 업종 프리셋 = 표준 템플릿, 하나로 |
| 영업 | 조건부 찬(**양보**) | 공개판이 중립이 되면 별도 발표 모드는 P2로. 남는 요구는 업종 템플릿과 링크·QR |
| 마케팅 | 조건부 찬 | 공개판 = 발표 모드로 통합. 문구는 확인된 상태에서만 자동 생성, 수작업 미화 금지. 업종·패키지 명칭 검수 |
| 신입·HRD | 조건부 찬 | 미확인 공백을 "협력 조달"로 바꿔 부르는 건 반대. 발표 모드가 교육 탭 기본 화면이 되면 안 됨 |

**주요 공방**
- 임원·UX·마케팅이 "공개판이 중립화되면 공개판 자체가 발표 모드"라고 하자, 영업은 **발표 모드를 P0에서 P2로 양보**했다. 요구는 업종 템플릿(I2)과 링크·QR 공유로 줄었다.
- 신입·HRD가 "미확인 공백을 '협력 조달'로 바꿔 부르는 건 반대"라고 하고 임원도 "확인 안 된 '공급 가능' 표기는 과장 광고 리스크"라고 했다. 영업은 "발표 모드는 숨겨 속이자는 게 아니라 확인 안 된 것을 단정하지 않는 표현 방식"이라고 답하며 신입의 우려와 같은 방향이라고 봤다.
- 연구소는 "확인되지 않은 것을 긍정 표현으로 덮는 것도 부정확하기는 마찬가지"라며 `panel-sourced` 확인 기기에만 허용하자고 했다.
- UX는 모드를 하나 더 만드는 데 반대해 "발표 보기" 토글로 축소안을 냈다. 현장은 발표 모드를 두더라도 "발표 모드" 표시를 화면에 두자고 했다.

**합의점**: 발표 모드는 연결·노드를 바꾸지 않는 표시 방식이다. 긍정 문구("협력 조달" 등)는 I3에서 확인된 항목에만 쓴다. 별도 모드는 우선순위를 낮추거나 공개판으로 흡수한다.
**남은 이견**: 별도 `?mode=present`(현장·연구소·신입은 조건부로 허용) vs 공개판 흡수(임원·마케팅) vs "발표 보기" 토글(UX).

```jsonc
"coverage": "owned|partial|affiliate|sourced|missing|na",   // sourced 신설 = 패널 구성품·타사 조달
"gapAssessment": {
  "supplyMode": "in-house|affiliate|panel-sourced|not-offered|unknown",
  "basis": "homepage-menu|catalog|bu-confirmed|rnd-confirmed",
  "confidence": "candidate|confirmed",           // candidate면 화면에 "공백 후보" 고정
  "evidence": [{ "type": "url|doc|meeting", "ref": "https://… 또는 문서번호", "note": "공개 가능 문구" }],
  "verifiedBy": "부서명(실명 금지)",
  "verifiedAt": "2026-12-05",
  "reviewDue": "2027-06-05",                     // 6개월 재확인, 지나면 자동 candidate 강등
  "ratingScope": { "required": "7.2~38kV", "offered": "7.2~25.8kV" },  // 정격 기준 partial 판정(선택)
  "publicNote": "공개판 노출 문구",
  "internalRef": "사내판 오버레이 키"
}
```
| 규칙 | 내용 |
|---|---|
| 축 분리 | 커버리지(보유 여부)와 공급 방식(자체/계열사/패널 내 조달/미취급)은 다른 축 |
| 검증 규칙 | `basis = homepage-menu`이면 `confidence = candidate`로 강제. `pcs`(owned인데 확인 메모)처럼 모순된 항목이 걸러짐 |
| 공개/사내 | 공개 JSON에는 `internalRef`까지만. 기술 인접도·로드맵·전략 옵션(임원 1라운드 제안 3)은 비공개 저장소의 사내 오버레이 JSON에 둠 |
| 정격 | `ratingScope`로 VCB(7.2~25.8kV vs 자료 UL VCB 27/38kV) 같은 정격 기준 판정 근거 |
| 통합 | 임원 검증 스프린트, HRD 검토 메타(`reviewedBy/At/sourceDoc`)와 같은 스키마·필드명으로 통일 |
| 타협선 | `sourced` 신설이 화면 부담이면 `supplyMode`만 채우고 표시는 기존 5상태. 단 공백 표 집계에서 panel-sourced는 "미보유" 수에서 제외 |
| 목표 | 4주 안에 15건(공백 12 + 일부 보유 3) `confirmed` 100% |

### 다른 의견
| 페르소나 | 의견 |
|---|---|
| 임원 | 근거 필드는 필수. 메인 범례는 5개 유지, "타사 조달"은 미보유의 하위 배지로도 충분. 1라운드: 확인 결과를 "실제 미보유 / 비공개 보유 / 계열사 / 범위 밖"으로 확정, 제품기획·영업이 1건씩 확인 |
