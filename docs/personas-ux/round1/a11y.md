# 1라운드 — 웹 접근성 전문가 (WCAG 2.2 AA)

## 1. 나는 누구 · 상황 · 기기
WCAG 2.2 AA 감사자이며, 스크린리더(NVDA·VoiceOver) 사용자와 함께 검증한다. 이 앱이 사내 교육·영업 포털로 쓰이려면 키보드만 쓰는 사람, 저시력(200~400% 확대) 사용자, 색각이상 사용자도 같은 과업을 끝낼 수 있어야 한다고 본다.
- 방법: 실행 중인 앱(127.0.0.1:4173)을 Playwright로 조작했다. 1440×900 화면, 200% 확대에 해당하는 720×450, 400%에 해당하는 320×256 / 360×225, 모바일 390×844에서 라이트·다크 두 모드를 보고, `prefers-reduced-motion`도 켜서 확인했다. 주요 화면 8곳은 @axe-core/playwright(wcag2a~22aa 태그)로 검사했다.
- 스크립트·스크린샷 폴더: `/private/tmp/claude-501/-Users-kjmoon-LSE-News/37bcf7f5-4ef4-4874-8316-789fc9001612/scratchpad/ux-a11y/` (아래에서는 파일명만 적음)

## 3. 좋은 점 (근거)
- **axe 위반은 1종류뿐**(라이트·다크 8화면 모두). 건너뛰기 링크, `lang="ko"`, 라우트별 `<title>`, h1 구조, 비교 표의 caption·`th scope`, 공백 표 셀의 aria-label("L4 보호: 보유 2, 패널 구성품 1")이 모두 잘 되어 있음.
- **커버리지 6상태가 색만으로 구분되지 않음**: 배지마다 기호(✓ ◐ ◆ ▣ ✕ –)가 있고, 타일 aria-label에 상태 문구가 들어 있음(`kb-panel-open.png`).
- 선의 종류는 색에 더해 굵기와 대시 패턴(전력 실선 2px / 신호 4-4 1.5px / 택1 8-5 2px / 참조 점선)으로도 구분되고, 연결 관계는 패널의 "연결 기기" 칩 텍스트로도 제공됨(1.1.1·1.3.1 대체 수단 있음).
- 포커스 링이 뚜렷함: 파란 2~3px outline(`kb-tab1.png`). 다크 모드의 선·테두리 대비도 모두 4.4:1 이상.
- 모바일 시트에는 드래그 핸들(40×4)을 대신할 "위로 올려 전체 정보 보기" 버튼이 있음(2.5.7 통과). 390px 화면에서 24px보다 작은 터치 대상 0개.

## 4. 문제
**높음**
1. **포커스가 패널 뒤로 가려짐 — 2.4.11 Focus Not Obscured (최소)**. 패널이 열린 상태에서 Tab으로 오른쪽 타일(버스웨이 등)에 가면 자동 팬이 패널 너비를 고려하지 않음. 그래서 포커스된 타일이 패널 밑에 거의 다 숨음(`obsc-n-busway.png`). 74개 중 6개는 타일 중심이 패널·계층 내비·미니맵에 덮임.
2. **패널까지 Tab 51회 — 2.4.3 포커스 순서, 2.4.1 블록 건너뛰기**. Enter로 기기를 선택해도 포커스가 패널로 가지 않고, 패널로 건너뛰는 링크나 단축키도 없음. 스크린리더 사용자는 패널이 열렸다는 사실도 모름(4.1.3).
3. **200% 확대에서 계통도를 사실상 쓸 수 없음 — 1.4.10 Reflow, 1.4.4**. 720×450에서 고정 헤더·탭·계층 칩·줌 도구가 약 206px를 차지함. 시트까지 열리면 계통도는 약 35px만 보임(`zoom200-panel.png`). 320×256에서는 본문 스크롤 영역(`app-main`)이 **71px**밖에 안 됨(비교·공백·교육 화면 모두). 제품 상세는 320px 너비에서 문서 폭이 622px가 되어 가로 스크롤이 생김(어느 요소 때문인지 확인 필요).
4. **Gap 모드에서 흐리게 처리한 타일 글자 대비 1.9:1 / 보조 문구 1.5:1 — 1.4.3**. 보유 타일을 opacity 0.3으로 흐리게 하는데, 이 타일은 여전히 포커스·클릭이 되는 활성 컨트롤이라 비활성 예외에 해당하지 않음. axe는 이 문제를 잡지 못함(`mode-gap-recloser.png`). 다크 모드에서도 2.4:1.

**중간**
5. **라우트 전환과 상태 변화가 안내되지 않음 — 4.1.3 상태 메시지, 2.4.3**. 검색 Enter, "공백 표 보기", 비교 담기·빼기, 공백 표 셀 필터 모두 live region 안내가 없고 포커스도 그대로임. 현재 live region은 줌 배율 "94%" 하나뿐인데, 팬·줌을 할 때마다 읽혀 소음만 됨(axe incomplete: aria-prohibited-attr).
6. **화살표 키는 화면만 움직이고 Home/End는 화면을 크게 튐 — 2.1.1, 2.4.7**. Home을 누르면 포커스된 타일이 y=1963으로, End를 누르면 y=-1282로 화면 밖에 나감. 계통도는 "트리·그리드" 성격이므로 화살표로 **연결된 이웃 기기**로 이동하는 게 기대 동작임.
7. **공백 후보(점선)와 확정(실선)이 타일 이름에 없음 — 1.3.1**. 계통도 타일 aria-label은 "미보유(공백)"까지만 말하고, 후보·확정은 테두리 모양으로만 알 수 있음(패널을 열어야 텍스트로 나옴).
8. **계층 내비 버튼 이름과 화면 글자 불일치 — 2.5.3 Label in Name** (axe 위반, 9~26건). 화면에는 "L1 초고압 765/345kV 4/9"가 보이는데 이름은 "L1 초고압 발전·송전 — 보유 4 / 전체 9"라서, 음성으로 "765 누르기"라고 말하면 실패함. 타일 aria-label("진공차단기, 보유")에도 화면 약어 "VCB"가 빠져 있어 같은 문제가 있음.
9. **교육 단계 버튼과 모드 탭의 현재 상태 표현이 제각각 — 4.1.2**. 교육 L1~L7 단계 버튼에는 `aria-current`/`aria-pressed`가 없음. 제품/Gap/교육 전환은 `aria-pressed`인데, 성격상 탭이나 `aria-current`가 더 맞음.

**낮음**
10. 보유(초록) 타일 테두리와 계층 배경 대비 2.9:1 (1.4.11). 배지 기호가 있어서 정보 손실은 아님.
11. 검색창 포커스 표시가 1px 테두리 색만 바뀌는 수준이라, 다른 컨트롤(2px outline)보다 약함(2.4.7은 통과, 2.4.13 AAA에는 미달).
12. 쪽번호 링크 "p.56"이 22×15px (2.5.8 — 간격 예외로 통과하는 경계선). 공백 표 "계통도에서 보기"는 높이 16px.
13. `prefers-reduced-motion`에서도 0.12s 전환이 그대로 남음(2.3.3 AAA, 실제 영향은 작음). 팬은 즉시 이동하므로 문제없음.

## 6. 다른 페르소나와 충돌할 지점
- **헤더를 숨기는 P4** ↔ 디자인·브랜드·영업 페르소나: 늘 보이는 검색과 모드 탭을 원함. 절충안은 "높이 600px 이하 / 2배 확대일 때만" 적용.
- **Gap 모드 흐림 완화(P5)** ↔ Gap을 강하게 강조하자는 쪽(영업·기획). 대비를 유지해도 회색 채움과 테두리 제거로 강조는 유지할 수 있음.
- **로빙 tabindex(P3)** ↔ 마우스 위주 사용자는 영향 없음. 다만 "Tab으로 모든 타일 순회"를 기대하는 기존 E2E 테스트와는 충돌할 수 있음.
- 비교 바·미니맵을 더 키우자는 제안이 나오면 2.4.11 가림이 늘어남. P2의 "보이는 영역" 계산이 먼저 필요함.

## 7. 성공 지표
1. 키보드만으로 "VCB 선택 → 비교에 담기 → 비교 표 열기"까지 **누르는 키 10회 이하**(현재 약 80회).
2. 720×450(200%) 화면에서 패널이 열려 있어도 **계통도가 화면 높이의 40% 이상** 보이고, 320px 너비에서 **가로 스크롤 0**. axe 위반 0과 Gap 모드 글자 대비 4.5:1 이상 유지.
