# 2라운드 — 웹 접근성 전문가 (교차 반박)

근거는 1라운드에서 직접 잰 값입니다(`round1/a11y.md`, 스크린샷 폴더 `scratchpad/ux-a11y/`). 다른 페르소나 4명의 보고서도 읽고 반영했습니다. 화면에 보이는 요소를 바꾸는 안에는 **[사용자 확인 필요]**를 붙였습니다.

## 합의 후보에 대한 의견 (반대는 없고 조건만 붙임)
- **A1** 찬성합니다. 1라운드에서 320px 화면의 제품 상세 문서 폭이 622px로 나왔습니다. 디자이너가 본 1,810px 높이, 현장이 본 1,168px 폭과 같은 원인(표 안 visually-hidden 요소의 기준 위치)일 가능성이 큽니다. 고치면 1.4.10 Reflow도 함께 해결됩니다. 회귀 검사에 `scrollWidth === innerWidth`(320·390·1440)를 넣어야 합니다.
- **A2+A3** 한 작업으로 묶어야 합니다. 위치 동기화(팬·계층 표시)를 하면서 포커스 이동을 빼면, 키보드 사용자에게는 화면만 바뀌고 포커스는 엉뚱한 곳에 남습니다. 자동 팬 기준은 패널·미니맵·비교 바를 뺀 "보이는 영역"이어야 합니다(지금은 버스웨이 등 6개 타일이 가려짐, 2.4.11). `prefers-reduced-motion`이면 애니메이션 없이 즉시 이동해야 합니다(디자이너 우려 반영).
- **A4** 찬성합니다. history push로 바꿀 때 뒤로가기로 돌아오면 포커스도 그 타일로 복원해야 합니다.
- **A5·A6** 찬성합니다. aria-label에도 같은 이름 사전을 써야 합니다. 2.5.3(계층 버튼 이름이 화면 글자와 다름) 수정과 같은 작업입니다.
- **A7** 찬성합니다. 검색 결과에 "옵션" 종류를 추가하면, 화면 글자뿐 아니라 option 이름에도 종류가 읽혀야 합니다. 지금 기기·제품이 그렇게 되어 있는 방식과 맞추면 됩니다.

## 쟁점별 입장

**I1. 화면 확보 방식: 하나의 규칙으로 묶을 수 있습니다 (입장 수정).**
"compact 화면" 상태 하나를 두고, 들어가는 길만 세 가지로 둡니다. ① 자동: 높이 600px 이하, 가로 모드, 200% 확대 ② 수동: 영업의 "발표 보기" 토글(`aria-pressed`, 주소에 저장) ③ 라우트: 계통도가 아닌 화면에서는 사이드바 범례를 접음(디자이너 안).
compact 상태에서는 헤더를 검색 한 줄로 줄이고, 계층 칩과 줌 도구는 겹쳐 띄우고, 패널은 오버레이로 띄웁니다. 가로 모드에서는 패널을 사이드 패널로 둡니다(현장 안).
1라운드 제가 낸 "스크롤하면 헤더 숨김"은 철회합니다. 숨은 헤더는 Tab으로 갈 때 포커스를 가리거나(2.4.11) 사라졌다 나타나 위치를 잃게 하기 쉽습니다. 크기 조건에 따른 고정 compact가 더 안전합니다.
근거: 200% 화면에서 계통도 35px, 320×256에서 본문 71px, 현장의 가로 모드 0px, 영업의 1024에서 465px. 원인은 모두 "고정 영역이 화면을 너무 많이 먹는다" 하나입니다. **[사용자 확인 필요]**

**I2. 운영 정보: 기본은 접고, 순서는 학습 포인트 뒤로 옮깁니다. "발표 보기에서만 숨김"에는 반대합니다.**
보기 모드마다 내용이 달라지면 스크린리더 사용자와 링크를 받은 사람이 서로 다른 화면을 보게 됩니다. 접힘은 `<button aria-expanded>`나 `<details>`로 만들고, 요약 한 줄("공백 확정 · 재확인 2027-05")은 접힌 상태에서도 보이게 합니다. 이렇게 하면 신입(S5)과 디자이너(G)의 요구를 같은 해법으로 채우고, 영업의 노출 우려도 해결됩니다. **[사용자 확인 필요]**

**I3. Gap 모드: 강하게 강조하는 데 찬성합니다. 다만 "다른 것을 안 보이게 만들어서" 강조하는 방식에는 반대합니다. 0개 계층은 자동 이동이 아니라 안내 링크로 해야 합니다.**
지금 보유 타일은 opacity 0.3이라 글자 대비가 1.9:1, 보조 문구는 1.5:1입니다. 이 타일은 여전히 포커스·클릭이 되는 컨트롤이라 1.4.3 위반입니다. 공백은 굵은 빨간 테두리, 후광, 배지, 이름의 "공백" 문구로 강조하고, 나머지는 사진 흑백 처리와 회색 테두리로 물러나게 하면서 글자는 4.5:1을 유지합니다. 이렇게 해도 영업이 원하는 대비 효과는 납니다.
자동 이동은 사용자가 요청하지 않은 화면 변화라 3.2.2 취지에 어긋나고, 현재 위치도 잃게 합니다. 대신 배너에 "이 계층 공백 0 · L1로 이동 →" 링크를 두고 live region으로 읽어 줍니다. 타일 이름에는 "공백 후보/확정"도 넣어야 합니다(1.3.1). **[사용자 확인 필요]** (흐림 정도가 바뀜)

**I4. 시작 카드: 조건을 지키면 찬성합니다.**
조건은 다음과 같습니다. 모달이 아니라 화면 안의 카드일 것, 포커스를 빼앗지 않을 것, DOM에서 계통도보다 앞에 둘 것, 닫기 버튼 24px 이상에 이름 "시작 안내 닫기"를 붙일 것, 계통도 타일이나 포커스를 가리지 않을 것(2.4.11), 닫은 상태를 localStorage에 저장하되 try/catch로 감쌀 것, 닫은 뒤에도 헤더 "도움말"에서 다시 열 수 있을 것. 영업·현장은 한 번 닫으면 다시 안 뜨므로 방해가 되지 않습니다.

**I5. 범례 필터와 Gap 모드: 하나의 기능으로 합쳐야 합니다.**
범례 6항목을 `aria-pressed` 토글로 만들고, "Gap 모드"는 그중 "미보유+일부"를 미리 골라 둔 상태로 정의합니다. 그러면 강조 방식이 I3과 같아지고 대비 규칙도 한 번만 지키면 됩니다. 필터 결과는 live로 알립니다("미보유 9개 강조"). 범례 용어 옆 ⓘ와 "택1" 배지는 용어집 항목과 연결합니다(`aria-describedby`나 링크). 마우스를 올려야만 보이는 툴팁에 기대면 안 됩니다(1.4.13). **[사용자 확인 필요]**

**I6. 로빙 tabindex: 마우스 사용자에게는 영향이 없습니다. 우선순위는 P1로 내립니다 (입장 수정).**
바뀌는 것은 Tab 순서뿐이고 클릭·드래그·휠은 그대로입니다. 영향받는 것은 ① 화살표로 화면을 옮기던 키보드 사용자(Shift+화살표로 옮김) ② Tab으로 모든 타일을 도는 E2E 테스트입니다. A3(선택하면 패널로 포커스 이동)만 해도 "패널까지 Tab 51회" 문제는 0회가 됩니다. 그래서 A3을 P0로 먼저 하고, 로빙은 그다음에 합니다. 화면 위 조작 안내 문구는 함께 고쳐야 합니다.

**I7. 자료 바로가기: 지금 순서를 유지하고 바로가기만 더하는 것으로 충분합니다.**
조건은 다음과 같습니다. 앵커를 누르면 스크롤만 하지 말고 섹션 제목(tabindex=-1)으로 포커스를 옮길 것, 링크 이름에 "PDF, 12MB, 새 탭"을 넣을 것, 터치 대상 44px 이상일 것. 지금 "자료 5건" SPAN은 눌러지는 것처럼 보이지만 눌러지지 않습니다. 버튼으로 바꾸든 장식으로 확실히 하든 둘 중 하나로 정리해야 합니다.

**I8. 오프라인: 한글 오류 안내와 "다시 시도" 버튼은 P0급으로 비용이 작습니다. 전체 캐시는 P2입니다.**
영문 스택 메시지는 이해할 수도, 복구할 수도 없습니다(3.3 취지). 오류 영역에 `role="alert"`를 달고 다시 시도 버튼에 포커스를 둡니다. 서비스워커는 해시가 붙은 청크만 캐시 우선으로 하고 데이터 JSON은 네트워크 우선으로 해서, 갱신이 늦게 반영되는 위험을 막습니다.

## 바뀐 입장 요약
- 1라운드 "헤더 자동 접기(스크롤 숨김 포함)" → 크기 조건과 발표 토글로 들어가는 **단일 compact 상태**로 바꾸고, 스크롤 숨김은 철회합니다.
- 1라운드 로빙 tabindex P1 유지 → A3 포커스 이동을 P0로 앞세웁니다.
- Gap 강조 약화 요구 → 강조는 유지하고 **대비만 지키는 것**으로 바꿉니다.

## I9. 우선순위
**다음 라운드에 반드시 할 것 (P0)**
1. **A1 문서 넘침 버그**(제품 상세·비교 바·320px 가로 스크롤). 회귀 검사 포함.
2. **A2+A3 위치·포커스 동기화**: "보이는 영역" 기준으로 팬하고, 선택하면 패널 제목으로, Esc를 누르면 타일로 포커스를 돌립니다. 동작 줄이기 설정 대응과 A4 history push도 함께 합니다.
3. **상태 안내용 live region 하나로 통일**: 비교 담기, 라우트 전환, 필터, 오류 안내. 줌 % 안내는 없앱니다. 라우트가 바뀌면 h1로 포커스합니다.
4. **Gap 모드 대비 수정**: opacity 대신 대비 4.5:1을 유지하고, 이름에 공백 후보/확정을 넣습니다(작은 변경, 확인 필요).
5. **I1 단일 compact 규칙**: 낮은 화면, 가로 모드, 200% 확대, 발표 보기. 화면이 크게 바뀌므로 사용자 확인 후 진행합니다.

**하지 말 것**
- Gap 모드에서 공백 0개 계층이면 **자동 이동하기**(위치를 잃고 예기치 않은 화면 변화가 생김).
- **스크롤하면 헤더가 사라지는 방식**(포커스 가림과 위치 혼란).
- "보이는 영역" 팬을 고치기 전에 **비교 바·미니맵을 키우거나 비교 정원을 늘려 하단 오버레이를 키우기**(2.4.11 가림이 늘어남).
- 운영 정보를 **발표 보기에서만 숨기기**(보기 모드마다 내용이 달라짐). 접힘 기본값 하나로 해결합니다.
