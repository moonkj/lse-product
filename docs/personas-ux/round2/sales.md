전제: 고객 앞에서 태블릿 1024×768(가로, 터치)과 노트북 1280×800을 씀. 근거는 1라운드 직접 조작 결과(`round1/sales.md`, 스크린샷 `/private/tmp/claude-501/-Users-kjmoon-LSE-News/37bcf7f5-4ef4-4874-8316-789fc9001612/scratchpad/ux-sales/`)와 다른 4명의 보고서 수치.
사용자 결정(공개/사내판 분리 안 함 등)은 다시 논의하지 않음. 기존 화면 요소를 바꾸는 안에는 **[사용자 확인 필요]**를 붙임.

## 합의 후보 A1~A7 — 반대 없음, 보충만
- **A1 찬성(P0)**: 비교 바가 안 보이면 고객 앞에서 "담겼나?"를 두 번 누르게 됨. 태블릿 1024에서 ACB 옵션 3개를 담았을 때는 비교 바가 정상으로 보였음(tab-15). 그래서 현상은 좁은 폭에서만 나타나는 것으로 보임. 회귀 테스트는 390·1024 두 폭으로 할 것.
- **A2 찬성(P0)**: 영업 과업 T3(검색 ACB → Enter)는 1024에서 성공했지만, 디자이너의 "전체 보기 18% 상태에서 검색하면 지도가 그대로" 재현은 발표 흐름과 똑같은 상황임(전체 보기로 범위를 보여 준 뒤 질문을 받아 검색). 자동 팬은 최소 60% 배율 + "보이는 영역" 기준이어야 함.
- **A4 찬성**: 발표 중 Esc를 실수로 누르면 주소가 `#/`로 돌아감(1라운드 L3). push 기록이 있으면 뒤로가기 한 번으로 복구됨.
- **A5 찬성 + 보충**: "개발 메모 숨김"에 "카탈로그 추출… HTTP Range… docs.json" 문구(신입 T5)가 들어가야 함. 고객이 실제로 읽는 위치(정격 사양 머리)에 있음.
- A3·A6·A7: 반대 없음. A7(TS250 검색)은 영업에도 유용함. 고객이 견적서에 적힌 형식명을 그대로 말하기 때문.

## 쟁점별 입장

### I1. 화면 확보 방식 → **절충: "화면 크기 규칙(자동)" + "발표 보기(수동)" 두 층으로 묶음**
- 규칙 1(자동, 모두에게): **사이드바는 계통도·Gap 화면에만**(디자이너 D). 비교·제품·공백 표에서는 1024 기준 콘텐츠 폭이 약 800px에서 1000px로 늘어남. 영업 비교 화면 가독성 문제(M1)의 절반이 이것으로 해결됨. **[사용자 확인 필요]**
- 규칙 2(자동, 낮은 화면): 높이 600px 이하 또는 2배 확대일 때 헤더가 스크롤과 함께 접힘(접근성 P4), 모바일 가로 모드에서는 사이드 패널(현장 P5). 1024×768·1280×800은 이 조건에 걸리지 않으므로 영업 발표에는 영향 없음 → **찬성**.
- 층 2(수동): 그래도 1024 계통도 화면은 사이드바 200 + 빈 상세 패널 360 때문에 계통도가 약 465px뿐임(1라운드 H1). 자동 규칙만으로는 해결되지 않으므로 **발표 보기 토글은 유지**함. 다만 범위는 "사이드바 접기 + 빈 패널 숨김(선택 시 오버레이)" 두 가지로 줄이고, 내부 메모 처리는 I2로 분리함.
- **입장 변경**: 1라운드에서는 발표 보기 하나로 다 해결하려 했지만, 비교·제품 화면은 디자이너 D(자동)가 더 낫다고 봄. 발표 보기는 계통도 화면 전용으로 좁힘.

### I2. 상세 패널의 운영 정보 → **"순서 뒤로 + 기본 접힘"을 모두에게 적용. 발표 보기 전용 숨김은 철회**
- 근거: R/C 패널에서 "홈페이지 목록에서 찾지 못함 — 실제 미보유 여부 확인 필요", 재확인 기한, 회의 메모가 학습 포인트보다 위에 있음(tab-30-rc). 신입(S5)과 디자이너(G)도 같은 결론이므로 3명이 합의함.
- 기본 화면에서 접어 두면 발표 보기 전용 장치가 필요 없고, 모드별로 다른 화면을 관리하는 비용도 없음. 패널에는 판정 요약 1줄("미보유 · 공백 확정")만 남기고 나머지는 "판정 상세 ▸"로 접음. 데이터는 그대로 두는, 표시 방식만의 변경이라 공개판 분리 결정과 충돌하지 않음. **[사용자 확인 필요]** (패널 순서 변경)
- 운영 담당이 펼친 상태를 기억(localStorage)하는 정도면 충분하다고 봄.

### I3. Gap 모드 표현 → **접근성 안(회색 채움 + 4.5:1)에 찬성. 공백 강조는 빨간 테두리·배지로 충분**
- 영업에게 Gap 모드는 고객용 화면이 아니라 사내 준비용임. 고객 앞에서는 "보유" 쪽을 보여 주는 게 목적이므로, 보유 타일이 1.9:1로 흐려져 읽히지 않는 게 오히려 문제임(tab-06-gap에서 TR·MCCB 라벨이 판독 불가).
- 강조는 빨간 테두리·✕ 배지·미니맵 빨간 점으로 이미 충분히 강함. 회색 채움으로 바꿔도 대비 차이는 유지됨.
- 공백 0개 계층에서는 **안내 링크에 찬성, 자동 이동에는 반대**. 발표 중 공유 링크(`?mode=gap&node=…`)로 들어갔는데 화면이 다른 곳으로 튀면 설명이 끊김.

### I4. 첫 방문 시작 카드 → **조건부 찬성**
- 조건 ① 주소에 파라미터(`node`, `mode`, compare 등)가 있으면 띄우지 않음(고객에게 보낸 공유 링크로 들어온 첫 화면에 카드가 뜨면 안 됨). ② 1회만, 닫으면 영구 저장. ③ 계통도를 가리지 않는 위치(빈 상세 패널 자리)에 둠. 이 자리는 지금 비어 있으므로(디자이너 13번) 새 오버레이를 만들 필요가 없음.
- 고객 태블릿이나 회의실 PC처럼 처음 쓰는 기기에서 고객이 직접 열 때도 고려해야 함. 문구는 "사내 신입"이 아니라 "처음 보시나요?"처럼 중립적으로.

### I5. 범례 클릭 필터 + 용어집 → **필터는 Gap 모드로 합치고, 범례는 "용어 설명(ⓘ)"만**
- 범례 "미보유 9"를 누르면 Gap 모드로 들어가고, "보유 56"을 누르면 보유만 강조하는 식으로 **기존 모드를 재사용**하는 것이 중복이 적음. 새 필터 체계를 하나 더 만들면 발표자가 지금 어떤 필터가 걸려 있는지 놓치기 쉬움.
- 용어집에 택1·참조 타일·공백 후보/확정·패널 구성품을 추가하는 데 찬성함. 고객이 "택1이 뭐예요?"라고 물을 때 바로 띄울 수 있음.
- 범례 동작 변경 **[사용자 확인 필요]**.

### I6. 계통도 키보드 로빙 tabindex → **찬성(영업 영향 없음)**
- 영업은 터치와 마우스만 씀. 로빙 tabindex는 탭과 클릭 동작을 바꾸지 않음. 프레젠터 리모컨(←/→ 키를 보냄)을 쓸 때 화면이 팬되는 대신 이웃 기기로 이동하면 오히려 발표에 유리함.
- 조건: 화살표 이동 시에도 자동 팬이 "보이는 영역" 기준일 것(A2와 같은 구현).

### I7. 제품 페이지 자료 바로가기 → **순서 유지 + 상단 앵커 칩으로 충분**
- 제품 첫 화면의 사진·제품명·"계통에서 하는 일"·버튼 줄(tab-12)은 고객 설명용으로 좋음. 자료를 맨 위로 올리지는 말 것.
- 현장 P3("자료 6건" 칩을 매뉴얼 앵커로)와 신입 S7(카탈로그 PDF 버튼)은 둘 중 하나로 합치는 게 좋음. 영업 입장에서 더 필요한 것은 **"옵션별 사양으로 이동" 앵커**임. 1024에서 정격 표까지 스크롤이 약 1화면 넘게 필요했음. 그래서 칩 줄을 `[옵션별 사양] [카탈로그 n] [매뉴얼 n]` 형태로 제안함. **[사용자 확인 필요]** (칩을 눌러지게 하는 시각 변화)

### I8. 오프라인 캐시·한글 오류 안내 → **한글 오류 안내 P0, 서비스워커 캐시는 P2(보류)**
- 한글 안내는 노력 S이고, 고객사 회의실 와이파이가 끊겼을 때 영문 스택 메시지가 뜨는 것을 막아 줌. 영업에게도 실수 방지 항목임.
- 서비스워커 사전 캐시는 사양 데이터가 "검수 전"이라 자주 바뀌는 시기에 **예전 사양을 고객에게 보여 줄 위험**이 있음. 캐시를 넣는다면 앱 셸과 썸네일만 캐시하고 데이터(JSON)는 network-first로 받아야 함. 현재 첫 로딩이 0.63초(로컬)이고 압축 전송량 약 450KB로 가벼우므로 급하지 않음.
