# 2라운드 — 현장 시운전·유지보수 엔지니어 (field)

기준: 1라운드 5개 보고서와 내가 1라운드에서 직접 측정한 값(390×844·360×740·844×390, LTE·400kbps·오프라인). 측정 스크린샷은 `/private/tmp/claude-501/-Users-kjmoon-LSE-News/37bcf7f5-4ef4-4874-8316-789fc9001612/scratchpad/ux-field/`에 있다.

## 합의 후보에 대한 의견
- **A1 찬성(동일 원인으로 봄).** 디자이너는 데스크톱 제품 페이지에서 `documentElement.scrollHeight` 1,810px(헤더 사라짐)를 봤고, 나는 모바일에서 innerWidth 1,168px(Smart MCCB)·450px(GIPAM1000)를 봤다. 접근성 전문가도 320px 너비에서 문서 폭 622px를 확인했다. 세 경우 모두 옵션 표가 있는 제품 페이지에서만 생기고, 표 안에 absolute로 배치된 `visually-hidden` 요소가 공통이다. 수정 1건으로 세 증상을 함께 검증하자(회귀 기준: 390px에서 `innerWidth === 390`, 1440px에서 `scrollHeight === innerHeight`).
- **A2 찬성 + 조건.** 모바일에서는 "보이는 영역"이 시트 위 약 217px밖에 안 된다. 연결 기기를 따라갔을 때 계전기 타일이 일부만 보였다(t7-1-follow). 그래서 자동 팬 기준은 **시트 높이를 뺀 영역**이어야 한다.
- A3·A5·A6·A7: 이견 없음. A4는 내 제안이다. 노드 선택을 replace에서 push로 바꾸면 Esc를 실수로 눌러 위치를 잃는 영업 L3 문제도 뒤로가기로 복구할 수 있다.

## 쟁점별 입장

**I1 화면 확보 — 절충: "콘텐츠 우선 규칙" 하나로 묶을 수 있다.**
네 제안 모두 "계통도 높이·폭이 일정 기준 아래면 크롬(헤더·사이드바·빈 패널)을 접는다"로 정리된다.
- 규칙: **보이는 계통도 높이가 viewport의 50% 미만이거나 높이 600px 이하이면 헤더를 접는다**(스크롤하면 사라지고 검색 아이콘만 남김). **폭 1100px 미만이면 빈 상세 패널을 두지 않고 오버레이로 띄운다.** **가로 모드(높이 500 이하)에서는 시트 대신 오른쪽 사이드 패널을 쓴다.**
- 영업의 "발표 보기"는 이 규칙을 데스크톱에서 수동으로 강제하는 토글로 두면 된다(같은 상태를 공유). 디자이너의 "사이드바는 계통도 화면에만"은 별개 규칙이지만 같은 방향이라 함께 적용할 수 있다.
- 근거: 모바일 세로에서 지도 217px(26%), 360폭 160px, 가로 0px(t9-3-land). 접근성 200% 확대 화면 35px. 영업 1024폭 465px. 모두 같은 원인이다.
- **사용자 확인 필요**(헤더 동작 변경).

**I2 운영 정보 — "순서는 뒤로 + 기본 접힘(1줄 요약은 노출)", 발표 보기 전용 숨김에는 반대.**
- 모바일 시트에서는 운영 정보가 자사 제품·매뉴얼 링크를 더 아래로 밀어낸다. 현장은 매뉴얼까지 가는 스크롤이 가장 비싸다.
- 발표 보기에서만 숨기면 모바일(발표 보기 없음)은 이득이 없다. 그래서 기본값부터 "판정 요약 1줄 + 상세 ▸"로 바꾸자.
- 데이터는 그대로 두고 표시 방식만 바꾸므로 공개판 분리 결정과 충돌하지 않는다. **사용자 확인 필요**(패널 순서 변경).

**I3 Gap 모드 — 접근성안 찬성, 자동 이동은 반대하고 안내 링크에 찬성.**
- 야외 직사광선에서는 opacity 0.3 타일(대비 1.9:1)이 사실상 안 보인다. 회색 채움으로 4.5:1을 확보하고 공백 타일은 굵은 테두리·채도로 강조하면, 영업이 원하는 대비 효과도 오히려 커진다.
- 자동 이동은 현재 위치를 잃게 만들고, 모바일에서는 지도 창이 작아 어디로 갔는지 알기 어렵다. "이 계층 공백 0 · L1(공백 n)으로 →" 링크가 낫다.

**I4 첫 방문 시작 카드 — 조건부 찬성.**
- 1회만 표시, 닫으면 영구, **딥링크(`?node=`·`/product/`)로 들어오면 표시하지 않음**. 현장 사용자는 대개 공유 링크나 검색으로 들어오므로 이 조건이면 방해가 없다.
- 모바일에서는 오버레이 대신 **검색창 아래 1줄 배너**(높이 44px 이하)로 하자. 지도 217px를 더 가리면 안 된다.

**I5 범례 필터 + 용어집 — 절충: 범례 클릭 = "그 상태만 강조"를 Gap 모드의 일반화로 통합.**
- Gap 모드는 "미보유·후보만 강조"로 미리 정해 둔 필터이고, 범례 클릭은 임의 상태 필터로 보면 된다. 상태 강조 엔진 하나에 진입점 둘로 정리한다.
- 모바일에는 범례 자체가 없다(신입 12번). 범례는 시트나 툴바의 "ⓘ 범례" 버튼(44px 이상)으로 꺼내자. 용어집 연결에는 찬성한다(택1·패널 구성품은 현장에서도 헷갈린다).

**I6 로빙 tabindex — 찬성(현장 영향 없음), 단 터치 동작 회귀 테스트를 조건으로.**
- 터치·마우스에서 탭 동작이 바뀌지 않는지 확인이 필요하다. 특히 타일을 탭하면 선택되는 동작과, 핀치 확대 75→200%가 정상인지 다시 측정해야 한다.
- 화살표로 연결 이웃 기기로 이동하는 모델은 내가 T3에서 칩으로 하던 "연결 기기 따라가기"의 키보드판이라 일관성 면에서 좋다.

**I7 제품 페이지 자료 바로가기 — "순서 유지 + 바로가기"로 충분하다(신입 S7과 통합).**
- 제품 상단에 `[매뉴얼 3] [카탈로그 2] [계통 위치]` 앵커/버튼 줄 하나를 두자. 기존 「자료 5건」 칩을 그대로 앵커로 만들면 새 요소도 거의 늘지 않는다. 사진·설명 순서는 영업 요구대로 유지한다.
- PDF 줄에 용량을 표시하자(느린 회선에서 12MB를 열지 말지 판단해야 한다). 측정값: 지금은 매뉴얼까지 약 2,070px, 스와이프 3~4번.

**I8 오프라인 캐시 — 범위를 줄여 찬성.**
- **1단계(S, P0)**: 청크 로드 실패 시 한글 안내와 "다시 시도" 버튼. 지금은 "Unable to preload CSS …"라는 영문 오류가 뜬다(t10-offline-nav). 이것만으로도 끊김 대응의 80%는 된다.
- **2단계(M, P2)**: 앱 셸·페이지 청크·썸네일만 사전 캐시. 데이터 JSON은 network-first(온라인이면 항상 최신)로 해서 갱신 지연 위험을 없앤다. PDF는 외부(ls-electric.com)라 캐시 대상이 아니다.
- 비용 대비 가치: 1단계는 매우 높고, 2단계는 GitHub Pages 배포 후 실제 현장 피드백을 보고 결정한다. 이번 라운드에서 2단계를 반드시 할 필요는 없다고 **입장을 낮춘다**(1라운드 P1 → 2단계는 P2).

## 바뀐 입장
- 오프라인: 서비스워커 전체 캐시(P1) → 한글 오류·재시도만 P0, 캐시는 P2로 낮춤.
- 화면 확보: "모바일 전용 헤더 접기"를 고집하지 않고 접근성의 높이 기준 규칙에 통합(가로 모드 사이드 패널은 유지).
- 시작 카드: 1라운드에서는 방해 요소로 볼 생각이었으나, 딥링크 제외 조건이면 찬성.

- **모바일 첫 화면 오버레이 카드**: 1줄 배너가 아니면 지도 창을 더 줄인다.
