# E4 백승우 — 선·모션 (round4)

## ① 다크·모바일
- **라이트 폭 맞춤(after3/11, 37%)**: #6fb1ea 3px 펄스가 이제 선 위에서 보인다. 3라운드 P0이 해결됐다.
- **다크 선택(after3/08)**: 트랙과 펄스는 좋다. 그러나 22.9kV 모선 #2b4a7a가 밴드와 명도가 비슷해, 트랙이 없는 구간에서는 모선이 사라진다.
  - **수정**: `--color-line-bus` 다크 **#6f93c6**.
- **다크 전체 흐름(확인 필요)**: 전력선이 밝은 #dfe4ea인데 펄스 #2f7fd0이 더 어둡다. 펄스가 흐르는 빛이 아니라 선이 끊긴 틈처럼 읽힐 위험이 있다.
  - **수정**: 전체 흐름이 켜진 동안 다크 `.dedge--power` opacity를 **0.6**으로 낮추거나, 펄스를 **#7cbcf5**로 선보다 밝게 한다. 밝게 하는 쪽이 낫다.
- **모바일(after3/09, 75%)**: 선택 경로가 잘 보인다. 다만 하류 경로가 아래 시트에 가려 펄스가 시트 밑에서 계속 돈다. 시트가 열리면 선택 기기와 모선이 시트 위 40% 지점에 오도록 자동으로 옮기기를 권한다. 화면 이동 동작이라 사용자 확인이 필요하다.

## ② 이번에 할 것(3개만)
1. **선택 펄스 44px/s, 대시 18/22**: flow.ts 상수 2줄. 지금 56px/s는 0.64초 주기라 깜빡이는 것처럼 보인다.
2. **다크 모선 #6f93c6**: tokens.css 1줄.
3. **상·하류 대시 구분**(상류 18/22, 하류 6/14): `role`은 이미 계산되어 있어 클래스 하나와 CSS 변수 2개면 된다.

다음 회차로 미룰 것은 선택 전환 페이드와 축소 시 화면 기준 최소 굵기(non-scaling-stroke)다. 효과는 있지만 화면 확인 비용이 커서 미룬다.

## ③ 성능·움직임 줄이기
- **전체 흐름은 filter 0개를 유지한다.** 빛 번짐은 선택 경로 그룹 하나에만 둔다. 약 70개 경로의 stroke-dashoffset 애니메이션이면 데스크톱은 여유가 있다.
- **모바일(`pointer: coarse`)**: 전체 흐름 속도를 **16px/s**로 낮춘다. 손가락 확대·이동 중, 그리고 시트를 끄는 동안에는 `is-panning`과 같은 방식으로 정지한다. 배터리와 발열을 줄이기 위해서다.
- **움직임 줄이기**: 전체 흐름을 **아예 숨긴다**. 선택 경로에만 트랙과 ▸ 화살표를 둔다. 지금 규칙대로라면 전력선 약 70개에 ▸가 달려 소음이 된다. 인쇄도 같은 규칙을 적용한다.
- **배율 다시 그리기**: 0.05 단위로 묶는 지금 방식을 유지한다. 15% 미만 정지 기준도 적절하다.
